# Security policy

## Supported version

Security fixes are applied to the latest commit on `main`. Preview builds and
older candidate tags do not receive separate support.

## Reporting a vulnerability

Do not open a public issue containing exploit details, credentials, private
content or personal information.

Use GitHub's private vulnerability reporting when it is available for this
repository. Otherwise, request a private reporting channel through the contact
route published on the repository owner's GitHub profile.

Include the affected route or source file, reproduction steps, impact and any
known mitigation. The owner will confirm receipt before discussing disclosure
or remediation timing.

## Scope

This policy covers the site source, content pipeline, generated static output,
GitHub workflows and deployment automation. Vulnerabilities in third-party
packages should be reported upstream as well when appropriate.
